# Сохранение корзины KITRADE — план

## Задача
Сохранить выбранные запчасти при переходах между главной, каталогом, категориями и страницами товаров, перезагрузке, возврате назад и повторном открытии браузера. Это корзина заявки на расчёт, без оплаты.

## Проверено в проекте
- catalog-app.js, product-page.js и product-quick-view.js используют общий ключ localStorage kitradeCatalogSelectionV1.
- Каталог при чтении исключает ID, которых нет в загруженном массиве товаров. Следующая запись может закрепить это сокращение корзины.
- Обработчиков storage и pageshow для синхронизации корзины нет.
- Черновик каталога сохраняет описание и комментарий, но не имя и контакт.
- Карточка товара дополнительно пишет отдельный черновик kitradeCatalogDraft в sessionStorage для главной формы. Нужен единый источник выбранных позиций.
- После подтверждённой успешной отправки каталог очищает выбранные позиции; при ошибке сохраняет их.

## Предлагаемый сценарий
1. «В заявку» добавляет товар один раз. Повторное нажатие открывает заявку; удаление выполняется явно внутри корзины.
2. В меню каждой страницы есть «Заявка · N». Счётчик показывает число разных позиций. На мобильном — компактное доступное управление с тем же счётчиком.
3. Ссылка открывает /catalog/#request. При заходе по якорю мобильная панель заявки открывается автоматически. На ПК фокус переводится на заголовок заявки без перекрытия шапкой.
4. Переход к главной форме подбора не очищает корзину. Форма явно показывает выбранные позиции, если они будут включены в запрос; пользователь может исключить их. Нельзя незаметно отправлять только последнюю добавленную деталь.
5. Пустая корзина предлагает вернуться к товарам или оставить запрос на подбор. Контактный шаг открывается после выбора товара.
6. Обновление, переход назад и новые вкладки сохраняют состав. Изменения синхронизируются через storage, pageshow и локальное событие обновления.
7. Очистка — только по явному действию пользователя или после подтверждения приёма заявки сервером. После отправки удаляются только отправленные позиции: товары, добавленные во время запроса, остаются.

## Хранилище
- Общий модуль cart-store.js, подключаемый ко всем страницам с меню и используемый всеми кнопками добавления.
- Версионированная запись: ID, количество (пока 1), дата добавления и краткий снимок товара — название, изображение, ссылка. Снимок нужен для отображения при недоступности исходных данных; цена из него не считается актуальной.
- При открытии заявки актуализировать информацию по ID. Отсутствующие позиции не удалять молча: показывать «Наличие уточняется» и разрешать удалить вручную.
- Миграция существующего массива ID без потери товаров. Перед каждой операцией читать актуальное сохранённое состояние, а не записывать устаревший массив страницы. Для одновременных операций между вкладками предусмотреть сериализацию и повторное слияние.
- Состав хранить между сеансами без автоматического удаления. Устаревшие сведения перепроверять при открытии. Очистка данных браузера удаляет локальную корзину; между устройствами она не переносится без серверного решения.
- При недоступном хранилище сохранять состояние в памяти текущей страницы и явно сообщать, что после её закрытия выбор может потеряться.
- Не связывать корзину с согласием на аналитику. Она обеспечивает запрошенную пользователем работу сайта.
- Имя и контакт не добавлять в долговременное хранилище по умолчанию. Для восстановления незавершённой формы внутри вкладки использовать отдельный sessionStorage-черновик. Галочку согласия автоматически не восстанавливать.

## Очерёдность реализации
1. Создать общий модуль и миграцию существующих ID.
2. Подключить каталог, быстрый просмотр, карточку товара и главную форму к модулю.
3. Добавить общий счётчик и переход к заявке в меню и шаблоны сборки.
4. Обработать восстановление страницы, несколько вкладок и недоступное хранилище.
5. Исправить очистку после отправки и обновление доступности товаров.
6. Пересобрать сайт и проверить пользовательские сценарии.

## Проверка перед сдачей
- Добавить A в каталоге, B в карточке товара, перейти на главную и обратно: обе позиции сохраняются.
- Перезагрузить, закрыть и вновь открыть браузер: состав восстанавливается.
- В двух вкладках добавить/удалить разные товары, затем вернуться назад: данные и счётчик совпадают.
- Перейти в другую категорию: товары вне категории остаются в заявке.
- Удалённый из каталога товар остаётся видимым с пояснением.
- Отказ от аналитики не меняет корзину.
- Ошибка отправки не очищает данные; успех удаляет только отправленные товары.
- /catalog/#request открывает заявку и на ПК, и на мобильном.

## Реализация — 7 сентября 2026

Выполнено:
1. Общее хранилище `cart-store.js` подключено к главной, каталогу, документам и шаблонам генерируемых страниц. Старые ID мигрируют автоматически; каждая позиция хранится отдельно, чтобы вкладки не перезаписывали весь состав.
2. Каталог, просмотр товара и отдельная страница товара используют общее хранилище. Позиции вне текущего набора данных сохраняются с пометкой «наличие уточняется».
3. В шапке вместо дублирующей телефон кнопки появилась «Заявка · N»; телефон сохранён. В мобильное меню добавлена ссылка на заявку.
4. Повторное нажатие «В заявке» открывает корзину. Удаление выполняется отдельной кнопкой. После подтверждения сервера удаляются только отправленные позиции.
5. Контактный черновик каталога хранится в sessionStorage; согласие не восстанавливается. Отказ от аналитики не влияет на корзину.
6. Отдельная страница товара направляет пользователя в корзину каталога, а не создаёт на главной черновик только последней детали. Форма подбора на главной остаётся отдельным сценарием; переход к ней не очищает корзину.
7. Полноэкранный просмотр закрывается стрелкой «Назад в каталог», Escape и кнопкой браузера. Сохраняются DOM каталога, фильтры, загруженные карточки и позиция прокрутки. Для переходов между страницами добавлен sessionStorage-снимок выдачи.
8. Карточки выделены рамкой и поверхностью; текстовые отступы сокращены, фото сохраняют полный кадр без увеличения при наведении.
